## 键盘弹出时欢迎语/输入框动画顺滑度优化（StockChatPage.kt）

用户反馈欢迎语 hide 和输入框变化不丝滑、感觉太快。根因与修复：

1. **欢迎语飞出太猛**：原实现飞出距离 0.72 倍页高（~600pt）且全程不透明，用欠阻尼弹簧 `springEaseOut(0.45, 0.8, 0.15)`（会回弹过冲），与 0.25s 的键盘动画脱节。改为：位移降到 0.35 倍页高 + 同步淡出（opacity 结合 `active && !flownUp`），曲线改 `easeOut(keyboardAnimDuration + 0.06f)`（比键盘慢半拍收束）。WelcomeContent 与 WatchlistPlaceholder 两处一致，且旧 `animation()` API 统一换成新 `animate()`（同视图同 key 新旧混用会抛"不支持新旧动画接口同时存在"）。
2. **输入框外框裸跳**：dock 根视图、消息区容器、渐隐层的 height/bottom 都依赖 composerFocused/voiceMode/inputLineCount，但之前只注册了 keyboardHeight 一个动画键 → 聚焦时内部面板播 0.26s 动画、外框瞬时跳变。修复：这三处补齐 `animate(easeInOut(0.26), composerFocused/voiceMode)` 和 `animate(easeInOut(0.18), inputLineCount)`，与内部面板/TextArea 完全一致。
3. **经验**：AnimationManager 按 (propertyKey, viewRef) 注册动画，一个视图可对多个 observable 各注册一条动画；`animate()` 绑定的是该调用前**最后一次读取**的 observable，所以多个 animate 连写时每个的第二个参数就是要绑定的 key。

验证：`:shared:compileDebugKotlinAndroid` + `:androidApp:assembleDebug` 通过。真机动画手感待回归确认。

## ~~收键盘时面板收缩动画提前到回落开始~~（已被下一节的交互改版替代）

用户反馈：键盘落完才播展开→收缩动画，慢半拍显卡。原实现（settleComposerAfterKeyboardDrop）故意把 composerFocused 的翻转延迟到回落播完，因为同帧翻转会打断回落动画（外层节点只给 keyboardHeight 注册了动画，聚焦态引发的几何变化走无动画帧更新，把在飞的回落动画打断）。

新方案：**立即翻转 + 外层几何冻结**。

1. `composerFocused` 在键盘开始回落时（keyboardHeightChange 高度归零分支 / resetKeyboardState）立即翻转为 false 并 blur——内部面板/TextArea/按钮行都给 composerFocused 注册了 0.2s 动画，收缩与键盘回落并行播放。
2. `keyboardDropSettling` 改为 observable，回落期间为 true。dock 外框高度、消息区容器 bottom、渐隐层 bottom 这三处只绑键盘动画的节点，展开态改用保持值 `composerDockExpandedHeld() = composerFocused || keyboardDropSettling`（extraInputLines 同理用 Held 变体）：聚焦态翻转时它们的计算值不变 → 无 diff → 不打断回落；回落播完（keyboardAnimDuration+0.03s 定时器）才解冻切到收起几何——外框透明、面板底部锚定，这次切换视觉无感（与旧方案 settle 时的 snap 时机一致，无回归）。
3. `dockSettleGeneration` 代次计数防旧定时器提前解冻（回落窗口内键盘再弹起又收起的场景）。homeContentHidden 绑定加上 keyboardDropSettling，欢迎区仍在回落播完后再回挂，时机不变。

真机回归失败：面板在原地播收缩动画但不跟键盘回落（冻结方案没按预期避免打断）。被下一节方案替代。

## 交互改版：展开态与聚焦态解耦，点空白才收缩（StockChatPage.kt）

用户拍板改交互：收起键盘后输入面板保持展开，点页面空白区域才收缩——收缩的意义是"焦点离开输入后还给页面空间"，不是紧跟键盘。这从根上消除了"收缩动画与键盘回落动画并发"的问题。

实现：

1. 新增 `composerExpanded` observable，与 `composerFocused` 解耦。所有"展开"视觉（面板高度/圆角、TextArea 位置与行数、按钮行、模型按钮、发送按钮、AI 声明 footer 透明度、extraInputLines）从 composerFocused 切到 composerExpanded；composerFocused 只留给焦点/键盘逻辑（placeholder 文案与 TextArea touchEnable 也切到 expanded，展开未聚焦时点输入区可原生重新聚焦）。
2. 聚焦入口（inputFocus、focusComposer、toggleVoiceMode 退出语音分支）同时置 composerExpanded=true。键盘回落分支只翻 composerFocused=false 并 blur，expanded 不动。
3. "空白区域" = 输入框以外的全部区域（用户澄清，含顶栏/聊天区，滑动聊天列表也算）。信号有三处：MainLayer 根容器的 click（没被子视图消费的点击冒泡到此）、消息区 Scroller 的 click 和 dragBegin（滚动容器消费触摸，到不了根容器，必须单独接；dragBegin 只在用户手势触发，程序化 setContentOffset 不会）。输入 dock 外框加了空的 click 吞掉区域内点击。消息菜单/模型菜单/抽屉的全屏遮罩各自有 click+touchEnable 门控，不会漏。
4. `handleBlankAreaTap()` 语义（第三版，用户确认滑动也要收缩）：键盘在场→blur+reset 收键盘，并置 `collapseComposerAfterSettle=true` 挂起收缩，回落定时器播完后执行（键盘动画结束后再播收缩，安全顺序）；键盘静止→立即收缩。聚焦入口（inputFocus/focusComposer/退出语音）清挂起标记。聚焦但键盘未弹起的边界：无回落窗口，立即收缩。
5. dock 外框、消息区容器、渐隐层三个外层节点：几何直接用 composerExpanded，并补回 `animate(easeOut(0.2f), composerExpanded)`（与 keyboardHeight 动画并存）。安全性依据：解耦后收缩只发生在键盘静止时；展开方向"expanded 先触发、键盘动画后接管"是之前真机验证过可行的顺序，出问题的只有"键盘回落中再触发展开类动画"这个顺序，现已不存在。startNewChat 里 composerExpanded=false 也因此放在 resetKeyboardState 之前。
6. 删掉上一版的 composerDockExpandedHeld/composerExtraInputLinesHeld 冻结方案；keyboardDropSettling+generation 保留，只用于：主页内容回挂延迟到回落播完、空白点击收缩的防打断窗口、nudge 兜底归位。
7. sendMessage / openModelMenu / openImagePicker 后面板保持展开（附件/语音本就有各自的展开贡献）；startNewChat 收缩。

验证：`:shared:compileDebugKotlinAndroid` 通过。真机待回归：重点场景=收键盘（面板应原地保持展开、整体跟键盘平滑回落）、点空白收缩、展开未聚焦时点输入区重新聚焦、多行文本与带附件的收键盘。
