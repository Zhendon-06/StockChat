# StockChat 共享组件说明

## AI 服务配置

文本问答等常规 AI 任务使用阿里云百炼 DashScope，语音输入与回答朗读使用 Xiaomi MiMo。
两个供应商的 API Key 相互隔离，不通过页面输入，也不写入 `commonMain`；Android 本地调试时
请在项目根目录 `local.properties` 中分别配置：

```properties
QWEN_API_KEY=你的千问_API_Key
MIMO_VOICE_API_KEY=你的_MiMo_API_Key
```

构建时也可用同名环境变量覆盖本地配置。千问文本问答只读取 `QWEN_API_KEY`，语音接口
单独读取 `MIMO_VOICE_API_KEY`，两者不会混用。

## 分层与依赖方向

共享代码按 `ui → controller → data → model` 分层。Kuikly 页面负责布局、渲染状态和转发用户动作，controller 注入数据源并编排加载、重试和错误状态，data 层封装网络/本地接口，model 只包含跨端数据结构。依赖只能向右流动，data 和 model 不依赖 UI；页面不直接创建数据源。`kuikly-chart`、`table-core` 是可独立复用的跨端组件库，平台工程只负责启动、路由容器和必要桥接。

## Markdown 文本选择与复制

AI 回答完成后，Android、iOS 和鸿蒙端支持在 KuiklyMarkdown 内容上长按选词，并拖动左右手柄
调整选择范围；松手后可点击“复制”写入系统剪贴板。流式生成期间暂不启用选区，避免内容尺寸变化
导致选区被框架取消。

Kuikly 的跨节点文本选区目前不支持 Web/小程序，因此这些平台保留消息操作栏的“复制整条回答”
作为明确降级路径。当前每个 Markdown 块维护独立选区，不能跨两个结构化回答块连续拖选。

免费默认 Provider 预置 `qwen3-vl-flash`、`qwen3-vl-plus`、`qwen-vl-plus` 三个视觉模型，均支持
流式输出，请求 DashScope OpenAI 兼容接口
`https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`；标的识别使用同一百炼 Key 下支持联网搜索的 `qwen-plus`，不再调用 Embeddings。语音识别使用
`mimo-v2.5-asr`，回答朗读使用 `mimo-v2.5-tts` 与 `mimo_default` 音色，统一请求
`https://api.xiaomimimo.com/v1/chat/completions`，并按 MiMo 官方协议使用 `api-key` 请求头。
Android 录音使用 16 kHz 单声道 PCM16，并封装为 WAV；单次录音限制为
300 毫秒至 30 秒。TTS 默认使用流式 PCM16 输出，Android 收到音频分片后立即交给
`AudioTrack` 播放；不支持原生流式桥接的平台保留非流式 WAV 降级路径。API Key 会进入客户端
构建产物，仅适合本地调试，正式环境应改为
服务端代理或短期凭证。

未配置模型 API Key 时提示配置；识别超时或返回无效 JSON 时展示失败与重新生成入口，不使用本地
教学模板、名称词典、代码市场猜测或 Mock 卡片作为自动回退。

## 行情数据与路由

每条用户消息涉及两条请求分支，模型菜单顶部的「回答模式」决定它们的编排方式，选择随模型配置一起持久化
（`ModelConfiguration.answerMode`），默认「更快回答速度」：

- **聊天分支**：携带会话上下文（问 A + 答 B + 问 D），经 `ContextWindowManager` 裁剪后发给当前选中模型，
  负责回答正文与流式输出。响应缓存的键由 Provider、模型、裁剪后的上下文和当前问题组成，命中时直接回放
  上次合并后的正文与行情卡片，不再发起任何请求。
- **标的分支**：只发送当前这一条消息（问 D），不带任何历史，每条对话都是一次独立的结构化请求：
  1. 百炼 `qwen-plus` 识别用户提到或实际想查询的企业、指数，返回名称、可选的交易所代码提示、上市状态和
     查询意图。「联网精准实时数据回答」模式下加 `enable_search=true` 与 `search_options.forced_search=true`
     联网确认（可解析产品开发商、行业筛选等隐含查询）；「更快回答速度」模式不联网，只靠模型知识。
     其他 Provider 用当前模型按已有知识识别，不加联网参数也不声称联网。没有提到任何标的时返回空数组，
     这条分支直接结束。由于看不到历史，无法独立解析的代词不猜测，只返回空数组。
  2. 并发（最多 6 路）使用返回的名称调用腾讯 `smartbox` 证券搜索；不按上市状态提前丢弃企业，
     返回空结果时说明该企业暂无可用证券。
  3. 识别请求给出的代码提示只在腾讯候选中存在时才被采用（成员校验，不是本地推断），这类企业不再发模型
     确认请求；其余候选连同用户原话（同样不带历史）交给当前模型确认。客户端只校验代码属于对应腾讯候选，
     不按名称相似度打分、不默认取搜索第一条。
  4. 通过确认的代码并发（最多 6 路）调用行情接口，卡片名称、价格、涨跌和时间均来自腾讯数据。

**更快回答速度（`AnswerMode.FAST`）**：两条分支同时发出。聊天分支的流式片段立即透出；标的分支一旦拿到
行情，卡片就随后续流式片段一起出现在正文下方，不等文字结束。聊天模型没有实时行情数据，系统提示词要求它
不得编造价格并引导用户查看卡片。

**联网精准实时数据回答（`AnswerMode.PRECISE`）**：标的分支先跑（百炼强制联网），拿到行情快照后拼进用户
消息再发聊天请求，正文可以引用真实价格并注明数据时间。卡片从第一个流式片段起就显示。开头等待更久，
换来正文里有可核验的实时数字。

两种模式最终都由 `ParallelAnswerJoin` 合并：聊天成功时把标的分支的说明（未上市、搜索为空、行情失败等）
追加到正文末尾，并按快照逐个附加 `MarketQuote` 卡片；聊天失败但行情成功时展示带“AI 深度解读当前不可用”
标记的行情卡片；两者都失败才展示失败与重新生成入口。标的分支的任何失败只降级为说明文字，不会让整条回答
失败。历史消息里的 `[行情标的:代码|名称]` 记录是此前卡片的行情，引用时须注明时间。

例如“腾讯、米哈游”，快速模式下聊天模型立即开始回答两家公司的情况，同时标的分支识别出两家企业并并发搜索
腾讯证券；腾讯控股的行情卡片一到就插入正文下方，米哈游搜索为空则在正文末尾单独说明。
图片问题仍直接进入视觉模型，不启动标的分支。

百炼联网搜索协议参考：https://help.aliyun.com/zh/model-studio/web-search 。OpenAI 兼容接口无法直接从
响应明确确认本次搜索是否实际执行；代码启用官方强制联网参数，不声称模型返回内容已经过事实核验。

沪深北及港股行情快照和日线使用腾讯证券 `newfqkline` UTF-8 JSON 接口，详情页及分时问题补充调用
`minute/query`。Web 端 `smartbox` 名称搜索存在 CORS 限制，部署时需要同域代理或相应网络适配。
卡片仍通过 Kuikly `RouterModule` 进入对应标的详情页，标记行情时间，并保留风险提示。

## 会话表格对比

聊天页的“会话表格对比”不是问答内容转抄，而是扫描当前会话中的用户消息、AI Markdown 和
`AnswerBlock.MarketQuote`，按交易所代码去重后汇总本次会话出现的全部可识别股票与指数。每个标的
保留“用户提及”“AI 生成”来源，并横向比较最新价、涨跌额/幅、今开、昨收、最高、最低、振幅、
换手率、市盈率、成交量/额、近期走势和行情时间；点击任意一行通过 Kuikly `RouterModule` 进入
`stock_detail` 详情页。

详情页的行情与 AI 解读通过同一张联动卡片承接：点击走势图中的节点会绘制纵向定位线和价格标记，
并更新该节点相对近期高低点的位置、相邻点变化和当前涨跌幅说明；“走势解读”“预测依据”“风险提醒”
三个焦点可以切换。点击“围绕此标的继续追问 AI”会通过 `RouterModule` 返回聊天页，预填包含标的、
选中节点和当前分析上下文的问题，用户可编辑后再发送，避免把详情页和 AI 分析割裂成两条流程。

对比页使用 `KuiKlyTableView` 的 `KuiklyTable` 承载横向滚动表格。进入页面后会按标的代码逐项刷新
腾讯行情；部分请求失败时保留会话中已有的结构化行情并明确标记降级状态，全部失败时仍展示已识别
标的而不伪造实时数据。当前可确定识别带交易所代码、六位代码、内置常用名称、历史行情标签及所有
结构化行情卡片；仅有名称且无法确定交易所的标的，需要先通过行情名称搜索或由 AI 同时给出证券代码。
页面统一展示“行情与 AI 结论均为演示信息，仅供参考，不构成投资建议”的风险提示。

## Mermaid 会话脑图

聊天页会话菜单中的“思维导图”会把当前单次对话整理为 Mermaid `mindmap` 语法，并将源码随产物
保存到本地会话数据库。生成内容以会话主题为根节点，每个问答分支包含问题、AI 摘要、相关标的和回答状态，
例如：

```text
mindmap
  root((市场复盘))
    1. 分析 600519.SH
      洞察：关注估值与现金流
      标的：600519.SH
      状态：已完成
```

详情页会解析已保存的 Mermaid 源码，并通过跨端 Kuikly 根节点、分层树干、分支节点和连接线渲染树状脑图，
不直接展示源码，保证
Android、iOS、Web 和鸿蒙均可浏览。旧版本已生成的脑图如果源码为空或解析失败，会使用已保存的分支结构
降级渲染。行情和 AI 结论仍标记为演示信息，并保留“仅供参考，不构成投资建议”的风险提示。

## 尺寸与适配

Kuikly 页面中的布局数值使用逻辑布局单位（Android 侧接近 dp，iOS 侧接近 pt），不是截图
里的物理像素。聊天页以约 `400` 逻辑宽度作为设计基准，通过 `StockChatLayoutMetrics` 对
关键间距、字体和控件尺寸做受限比例调整，并使用 `pageViewWidth` 计算 Drawer 与欢迎主视觉，
避免在不同屏幕上整体放大。欢迎 Logo 单独限制在约 `110–128` 逻辑单位，避免原先接近整屏宽。

## Markdown

聊天回答的 `AnswerBlock.Markdown` 使用 `KuiklyMarkdown` 1.0.6，并保留
`fallbackText` 作为空源文本或组件不可用时的降级内容。行情卡片与 Markdown
块分别渲染，避免把结构化行情压成纯文本。

表格通过 `markdownComponents(table = …)` 替换为应用侧的 `MarkdownScrollableTableView`：库默认实现让每列
`flex(1)` 平分宽度，列多时单元格文字互相覆盖。替换实现按单元格文本估算列宽（全角字符一 em，拉丁字母和
数字约 0.58 em，每列限制在 3 到 14 em 之间，超长内容在列内换行）；估算总宽放得下时按比例铺满消息宽度，
放不下时整表放入横向 `Scroller`，纵向手势仍交给消息列表。Kuikly 横向 Scroller 的内容视图是绝对定位的，
不会随内容长高，因此先按行数估算高度，再用 `layoutFrameDidChange` 回读真实高度。表头加粗并保留分隔线，
`:---:` 与 `---:` 分别对齐居中和右侧。

## 走势绘制

走势区域当前使用 Kuikly `Canvas` 绘制轻量折线，并绘制纵坐标轴、网格和价格刻度。
图表容器通过 Kuikly `pinch` 实现横纵方向的同步缩放，通过横向 `pan` 浏览放大后的
时间区间；空数据和单点数据均有保护。看板中的“AI 预测”按钮不会在本地对走势做
均值、斜率或随机外推，而是通过当前设置的模型 Provider 请求真实模型。请求上下文
包含腾讯行情快照、标的代码、行情时间、历史走势点和预测周期，并要求模型返回可校验
的结构化预测结果（预测点及其方向、依据和不确定性）。只有请求成功且结果通过校验后，
页面才绘制预测区间，并明确标记模型、生成时间和数据时间；历史走势与预测区间分段展示。

预测请求期间按钮进入加载态并避免重复提交。未配置 API Key、行情数据不足、网络请求
失败或模型返回空/非法结果时，只展示明确的不可用或错误状态并保留原始走势，绝不降级
为本地伪造曲线、固定点位或 Mock 预测。预测结果和 AI 解读始终附带“仅供参考，不构成
投资建议”的风险提示。

聊天中的 `MarketQuoteCard` 同步展示一段两行以内的“AI 观察”摘要，作为进入详情联动分析前的上下文
预览；详情页点选节点后的说明仍然只基于当前行情快照和已返回的模型结果，不伪造实时数据。

已评估 `KuiklyChartView`：该组件当前没有与本项目 OpenHarmony target 对应的发布变体，
为一个固定尺寸的走势图引入它会阻断跨端变体解析。因此保留 Canvas 作为跨端实现；
后续需要 Tooltip 或多序列时，可在补齐 OHOS 变体后替换为 `KuiklyChartView`。
